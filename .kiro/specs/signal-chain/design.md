# Design: signal chain (The Wire)

Generated by Kiro from `requirements.md`. This design covers the data path from a
message payload to an engine event, through framing, CRC, FSK modulation, the
seeded simulated channel, and the three transports. It names a correctness
property for every requirement marked **(PBT)** in the spec and gives the
`fast-check` shape each property test will take.

## Scope and boundaries

- New code lives in `src/channel/`, `src/modem/`, `src/transport/` only.
- Import direction stays one-way: `transport -> modem/channel -> engine`. `engine`
  imports nothing from these folders; the engine integration (Requirement 5) is
  satisfied by transports emitting plain event objects the existing reducer
  already understands, not by the engine reaching outward.
- Pure DSP and channel logic are functions over `Float32Array` / byte arrays with
  no DOM and no audio hardware, so they run in Node under Vitest. The AudioWorklet
  and `getUserMedia` wrappers are thin shells tested only by the manual checks
  recorded in `docs/RESULTS.md`.
- Randomness comes only from `src/channel/prng.ts`. `Math.random` and `Date.now`
  are banned in `src/engine`, `src/channel`, `src/modem` (tech steering).

## Module map

| Module | Responsibility | Pure? |
| --- | --- | --- |
| `src/channel/prng.ts` | Seeded deterministic PRNG (uint32 seed → stream) | yes |
| `src/modem/crc.ts` | CRC-16 over a byte array | yes |
| `src/modem/frame.ts` | `frame(payload)` / `parse(bytes)`: preamble + sync + length + payload + CRC-16; typed `PayloadTooLargeError`; `GarbledFrameError` surfaced as a parse result, not a throw | yes |
| `src/modem/fsk.ts` | `modulate(frame, sampleRate)` → `Float32Array`; `demodulate(samples, sampleRate)` → frame bytes. Binary FSK, continuous phase, Goertzel/quadrature per symbol, clock recovery from preamble | yes |
| `src/channel/channel.ts` | Seeded simulated channel: applies delay, drop, bit-flip, collision per scenario channel profile and send times; emits `received \| garbled \| collision` | yes |
| `src/transport/types.ts` | `Transport` interface: `send(frame)` + event emitter for `received \| garbled \| collision` | n/a |
| `src/transport/loopback.ts` | Two-tab transport over `BroadcastChannel`, impairments from the simulated channel | partly (BroadcastChannel shell) |
| `src/transport/scripted.ts` | Solo partner: replays a fixed send schedule through the simulated channel | yes core |
| `src/transport/acoustic.ts` | Speaker→mic via Web Audio + AudioWorklet; reports airtime and signal level | no (hardware) |

## Data model

- **Frame bytes:** `[preamble…][sync word][length: 1 byte][payload: 0–64 bytes][CRC-16: 2 bytes]`.
  Preamble is alternating bits for clock recovery; sync word is a fixed constant
  for frame-start detection (values tuned in `src/modem` and recorded in
  `docs/RESULTS.md`).
- **Parse result:** a discriminated union — `{ ok: true, payload }` or
  `{ ok: false, reason: "garbled" | "bad-sync" | "bad-length" }`. A bad CRC yields
  `garbled`; the payload is never delivered as valid and never silently repaired.
- **Channel profile:** `{ minDelay, maxDelay, dropProb, bitFlipProb }` scripted per
  time window by the scenario (spec glossary).
- **Channel event:** `{ kind: "received" | "garbled" | "collision", simTime, sender, recipient, payload? }`,
  shaped so a transport can hand it to the existing engine reducer as exactly one
  appended event (Requirement 5.1).

## Determinism contract

Every impairment decision (whether a frame drops, how far it is delayed, which
bits flip, whether two frames collide) is drawn from the PRNG seeded by the run's
seed. Given the same `(seed, channel profile, ordered send times)`, the channel
emits an identical event sequence. This is the backbone that makes the loopback
and scripted transports reproducible and the Séance replayable.

## Correctness properties (PBT requirements)

Each property below maps to one spec requirement. Tests live beside the module as
`*.prop.test.ts` (structure steering) and use `fast-check`. On failure, print the
fixed `seed` and paste the counterexample into a sibling example `*.test.ts` once
fixed (testing steering).

### P1 — Framing round-trip (Req 1.1)
> For any payload of 0–64 bytes, `parse(frame(payload))` returns a payload equal to the input.

- **Arbitrary:** `fc.uint8Array({ minLength: 0, maxLength: 64 })`.
- **Assertion:** parse result is `ok` and `payload` deep-equals the input, including
  the empty-array and 64-byte boundaries.
- **File:** `src/modem/frame.prop.test.ts`.

### P2 — Single-bit flip is always caught (Req 1.2)
> For any framed payload and any single bit position in the frame, flipping that one bit makes the frame parse as garbled; the payload is never delivered as valid.

- **Arbitrary:** payload `fc.uint8Array({ maxLength: 64 })` plus a bit index
  `fc.nat` reduced modulo the frame's total bit length.
- **Assertion:** after flipping exactly one bit, the parse result is `ok: false` with
  `reason: "garbled"` (or a sync/length failure that likewise does not deliver a
  valid payload). Never returns `ok: true` with the original payload.
- **Note:** this is the CRC-16 guarantee; `src/modem/crc.prop.test.ts` additionally
  asserts the CRC value changes for any single-bit input change.
- **File:** `src/modem/frame.prop.test.ts` (+ `crc.prop.test.ts`).

### P3 — Modulate/demodulate recovers the frame at both sample rates (Req 2.1)
> For any frame, modulating to samples and demodulating with no added noise recovers the identical frame at 44.1 kHz and 48 kHz.

- **Arbitrary:** payload `fc.uint8Array({ maxLength: 64 })`; sample rate
  `fc.constantFrom(44100, 48000)`.
- **Assertion:** `demodulate(modulate(frame(payload), sr), sr)` yields bytes equal to
  `frame(payload)`, so the parsed payload matches the input. No noise added.
- **File:** `src/modem/fsk.prop.test.ts`.
- **Related non-PBT:** Req 2.2 (≥95% recovery at ≥12 dB SNR over a 200-frame seeded
  trial) is a measured seeded trial, not a universal property — it runs as a
  fixed-seed statistical test and the measured rate is recorded in
  `docs/RESULTS.md`, not asserted as holding for every input.

### P4 — Channel is deterministic under a fixed seed (Req 3.1)
> For any seed, channel profile and list of send times, two independent channel runs produce the identical sequence of deliveries, drops, garbles and collisions.

- **Arbitrary:** `fc.record({ seed: fc.nat, profile: arbProfile, sends: fc.array(arbSend) })`
  where `arbProfile` bounds delay/drop/flip and `arbSend` is `{ sender, recipient, sendTime, payload }`.
- **Assertion:** `run(seed, profile, sends)` deep-equals a second `run(seed, profile, sends)`
  — identical ordered event list.
- **File:** `src/channel/channel.prop.test.ts`.

### P5 — No frame is delivered before send time + minimum delay (Req 3.3)
> For any seed, profile and send times, every `received` event's delivery time is at least its send time plus the profile's minimum delay.

- **Arbitrary:** same generators as P4.
- **Assertion:** for every emitted `received` event, `deliveryTime >= sendTime + profile.minDelay`.
  Dropped and collided frames produce no `received` event, so the bound is vacuously
  respected for them.
- **File:** `src/channel/channel.prop.test.ts`.

### P6 — Replay reaches the same state without any transport (Req 5.2)
> For any event log, replaying it through the engine reaches the same state as the live run, and replay touches no transport.

- **Arbitrary:** `fc.array` of channel events (`received | garbled | collision` with
  sim-time, sender, recipient, outcome) in arbitrary recorded order.
- **Assertion:** folding the log through the existing reducer twice gives equal final
  state; replay calls no transport method (verified with a transport test double
  whose methods throw if invoked). This extends the engine's existing deterministic
  replay tests to the new channel event types rather than replacing them.
- **File:** `src/engine/replay-channel.prop.test.ts` (engine-side; keeps the current
  `src/engine/engine.test.ts` suite untouched and passing).

## Non-PBT requirements and how they are verified

| Req | Statement | Verification |
| --- | --- | --- |
| 1.3 | Payload > 64 bytes rejected before transmit with a typed error | example test: `frame(65 bytes)` throws `PayloadTooLargeError` |
| 2.2 | ≥95% frame recovery at ≥12 dB SNR, 200-frame seeded trial | fixed-seed statistical test; measured rate recorded in `docs/RESULTS.md` |
| 2.3 | A transmitting device does not decode incoming audio (half-duplex) | example test on the transport state machine: decode suppressed while `transmitting` |
| 3.2 | Overlapping frames → `collision` to both, deliver neither | example test: two sends whose airtimes overlap emit `collision` to both and no `received` |
| 4.1 | Three transports behind one `Transport` interface | type-level + example tests: each implements `send` and the event contract |
| 4.2 | Mic denied/unavailable → fall back to loopback/scripted and say so in text | example test: denied-permission path selects fallback and surfaces a text message |
| 4.3 | Acoustic receive reports airtime and signal level as event metadata | manual audio check (hardware) recorded in `docs/RESULTS.md`; unit test on the metadata-shaping function with synthetic inputs |
| 5.1 | One transport event → exactly one appended engine event with sim-time, sender, recipient, outcome | example test: each `received/garbled/collision` appends exactly one well-formed event |

## Open design points (decide before implementing)

These are genuine choices the spec leaves open. They are flagged, not pre-decided.

1. **Sync word value and preamble length** — spec and modem steering give starting
   tones (1200/2200 Hz, 150 baud) but not the sync constant or preamble bit count;
   to be tuned by measurement and recorded in `docs/RESULTS.md`.
2. **CRC-16 polynomial** — CCITT vs IBM/ARC. Either satisfies P2; pick one and note it.
3. **Collision definition** — exact airtime-overlap test (strict interval overlap vs
   overlap including guard time). Affects Req 3.2 boundary cases.
4. **Channel event time unit** — whether channel sim-time shares the engine's
   sim-time unit directly or is converted at the transport boundary (Req 5.1).

## Test and verification strategy

- Pure modules: example tests pin human-describable behaviour; `*.prop.test.ts` pin
  P1–P6. Fixed seed printed on failure.
- No canvas snapshots; the waterfall/spectrum is fed by a pure data function tested
  on its output.
- Audio-hardware paths (acoustic end-to-end, airtime/level metadata from a real mic)
  are manual checks with steps and results in `docs/RESULTS.md`.
- Gate: `pnpm typecheck`, `pnpm test`, `pnpm build` all pass; the existing
  `src/engine/engine.test.ts` suite stays green throughout.
