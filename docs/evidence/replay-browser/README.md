# Replay browser test, seance-replay task 2.5

Run on 2026-11-23 (local time) against the assembled `dist/` from `pnpm build`.

- Server: `python3 -m http.server` on `127.0.0.1`, a fresh port for each build (48731 for the first build, 48732 for the final build after the kit fix). Stopped when done. Temp directories were not deleted.
- Browser: Playwright MCP, Chromium. I could not create a separate browser context through the MCP tools. A fresh port is a fresh origin, so localStorage, service workers and caches started empty (checked on 48732: `localStorage` had no keys before the first click). The service worker registered for `/dead-air/` during the run.
- Every observation below was taken on the final build (port 48732) unless it says "first build".
- "Seeded" means I wrote the state into `localStorage` with the real shapes (`dead-air:run` is `{version, scenarioId, seed, mode, log}`, and `dead-air:run:role`), reloaded, and the app answered "Resumed your saved run." The shapes were copied from a run I had just played through the UI. The simulated time in a seeded save is not something the game would produce by hand; it is a valid save.

## Bug found and fixed

**A decision made at the last time in the record did not fade anything.** In step (a), selecting the only decision (sim-minute 7, the last time on the axis) set `aria-pressed` and showed the sentence, but no signal or fact was faded. Cause: `layoutWorldlines` treats a cursor at or past the last time as the closed record and drops the focus. Fix, one condition in `packages/hindsight/src/replay/worldlines.ts`: the record is closed at the last time only when no participant is in focus. Test: `moment.test.ts`, "still fades what the focus did not know when the cursor is at the last time". `in-transit.prop.test.ts` now states the same closed rule. Before: 0 faded elements for the decision at 7 (`d-dead-air-solo-decision-selected-1280x720.png`, first build). After: the three facts on Field Lead's line are faded (`d-dead-air-solo-decision-selected-after-fix-1280x720.png`).

A consequence I kept: with a focus at the last time, a send that never got an outcome is drawn as "in transit" (faded, cut at the cursor) and the text timeline says it is on its way, which matches the sentence panel ("Not yet arrived"). The closed record, with no focus, still shows it as a dotted never-arrived stub.
